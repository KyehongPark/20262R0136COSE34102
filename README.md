이것은 고려대학교 운영체제 실습 레포지토리이며, 관련 내용을 정리하고자 한다.

Project 1은 커널 안에 정수 스택을 두는 시스템 콜이다. 리눅스 커널 6.6.36에서 연결 리스트로 스택을 들고 있고, 유저 프로그램에서는 syscall로 os2026_push(335), os2026_pop(336), os2026_clear(337)를 호출해서 이 스택을 push, pop, clear한다.

시스템 콜 번호는 syscall_64.tbl에 넣고, 함수 원형은 syscalls.h에 적었다. 핸들러는 SYSCALL_DEFINEx로 작성했다. 스택 노드는 kmalloc으로 만들고 빠질 때 kfree로 반환했다. 프로세스가 동시에 들어오면 리스트가 꼬일 수 있어서 DEFINE_MUTEX로 os2026_stack_lock을 만들었고, 스택을 만지는 부분은 이 락 안에서만 처리했다. 출력은 printf 대신 printk를 썼고, 동작은 dmesg로 확인했다.

Project 2는 가상 CPU ku_cpu랑 프로세스 스케줄링이다. 커널 안에 코어 하나짜리 ku_cpu를 만들어 두고, 사용자 프로세스들이 0.1초마다 os2026_ku_cpu(339)를 호출하면서 CPU를 요청한다. 요청이 들어오면 FCFS, SJF, RR 중 해당 정책으로 작업을 배정하고, 프로세스별 response time이랑 waiting time을 측정해서 비교했다.

누가 요청했는지는 current->pid로 구분했다. current가 리눅스 PCB인 task_struct를 가리키고 있어서 pid를 바로 볼 수 있다. 가상 CPU가 비어 있는지, 아니면 누군가 점유 중인지도 따로 기록하고, 바로 실행하지 못한 프로세스는 대기 큐에 넣었다.

FCFS는 선점하지 않고 대기 큐에 먼저 들어온 순서대로 CPU를 줬다. SJF는 남은 작업 시간 job_time이 가장 짧은 프로세스를 먼저 골랐다. 평균 대기 시간을 줄이려고 이렇게 했다. RR은 선점형이고 time quantum은 10 tick, 즉 1초로 잡았다. 시간이 다 되면 현재 프로세스를 대기 큐 맨 뒤로 보내고 다음 프로세스한테 CPU를 넘긴다.

수업에서 다룬 내용도 실습이랑 겹치는 부분 위주로 같이 적어 둔다.

운영체제 구조를 볼 때 policy랑 mechanism을 구분했다. policy는 무엇을 할 것인지이고, mechanism은 그 목표를 어떤 알고리즘이랑 자료구조로 만들 것인지다. 둘을 분리해야 설계가 덜 꼬인다.

실행 모드는 커널 모드랑 유저 모드로 나뉜다. 하드웨어 권한으로 나누며, 커널 모드는 특권 명령이랑 CR3 같은 제어 레지스터에 접근할 수 있다. 유저 모드는 그 권한이 없다. 유저 프로그램이 시스템 자원을 마음대로 건드리지 못하게 하려는 구분이다.

커널 종류도 비교했다. 모놀리식 커널은 서비스가 한 주소 공간에서 같이 돌아서 빠르다. 마이크로커널은 기능을 서버 프로세스로 나누고 IPC로 통신한다. 호출 비용은 더 들지만, 한 서비스가 죽어도 커널 전체가 같이 죽지는 않아서 고치기는 편하다. 가상화는 하이퍼바이저가 하드웨어를 추상화하고 그 위에서 게스트 OS를 여러 개 돌린다. 컨테이너는 그보다 가벼워서 cgroup이랑 namespace로 프로세스를 격리한다.

이벤트가 들어오는 방식은 트랩이랑 인터럽트로 나눴다. 트랩은 지금 실행 중인 명령 때문에 동기적으로 발생한다. 시스템 콜을 부르거나 0으로 나누는 경우가 여기 해당한다. 그러면 커널 모드로 넘어가서 핸들러를 실행하고 결과를 돌려준다. 인터럽트는 타이머, 디스크, 네트워크 카드처럼 현재 프로세스랑 상관없이 밖에서 비동기로 들어온다. ISR이 처리하고, 일정 시간마다 CPU를 나누는 시분할도 타이머 인터럽트가 있어야 된다.

프로세스는 실행 중인 프로그램이다. 프로세스마다 가상 주소 공간이 따로 있고, 그 안에 텍스트, 데이터, BSS, 힙, 스택이 있다. 그래서 다른 프로세스 메모리를 그냥 침범할 수 없다. CPU를 다른 프로세스에게 넘길 때는 레지스터, PC, 페이지 테이블을 가리키는 CR3를 PCB에 저장하고, 다음에 실행할 프로세스 PCB에서 다시 읽어 온다. 리눅스의 PCB는 task_struct다. 권한만 바뀌는 mode switch보다 저장하고 복원할 것이 많아서 context switch가 더 무겁다.

상태도 계속 바뀐다. new에서 시작해서 ready, running, waiting을 오가다가 terminated로 끝난다. 리눅스에서는 fork로 부모 프로세스를 복제하고, exec로 새로운 프로그램 이미지를 덮어쓰고, wait으로 자식이 종료될 때까지 기다린다.

스케줄링은 CPU burst랑 I/O burst가 반복된다는 전제에서 봤다. 연산 한 뒤에 입출력을 기다리고, 다시 연산을 하는 식이다. 실제 프로세스 대부분은 CPU burst가 짧다. 스케줄러는 CPU 이용률이랑 처리량을 높이고, turnaround time, waiting time, response time은 줄이는 방향으로 고른다.

우선순위만 보면 순위가 낮은 프로세스가 계속 밀리는 starvation이 생긴다. aging은 기다린 시간에 비례해서 우선순위를 올려 이 문제를 줄인다. MLFQ는 큐를 여러 개 두고, 프로세스 특성에 따라 큐 사이를 이동시킨다. 이렇게 하면 대화형 작업의 응답이랑 배치 작업의 처리 효율을 한 정책 안에서 같이 맞출 수 있다.

프로세스 사이 통신은 공유 메모리랑 메시지 전달로 구분했다. 공유 메모리는 shm_open이랑 mmap으로 커널이 잡아 둔 영역을 각 프로세스 주소 공간에 매핑한다. 이후에는 커널을 거치지 않고 직접 읽고 써서 빠르다. 대신 여러 프로세스가 동시에 같은 곳을 고치면 값이 깨지므로, 동기화는 사용자 쪽에서 해야 한다. 메시지 전달은 커널이 데이터를 복사해서 넘기고, 동기화도 커널이 맞춰 준다. 시그널은 비동기로 이벤트를 알리는 용도이고, 파이프는 한 방향 바이트 스트림이다. 메시지 큐는 메시지를 하나씩 넣고 빼는 우편함 형태이고, 소켓은 IP랑 포트로 네트워크 밖과도 통신할 때 사용한다.
